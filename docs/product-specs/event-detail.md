# Product spec — Event detail

## Goal
Give enough factual and social context to decide whether to attend and make the next action obvious.

## Required hierarchy
Image → time/title → venue/area → primary CTA → capacity → attendees/Pods → organizer/trust → description → practical restrictions/accessibility/cost → safety/source → share/report.

## Event origins
Imported, Organization, Community, Platform are visibly distinguishable where source matters. Verified organization is explicit.

## States
Open, approval required, full, waitlist available, joined, request pending, cancelled, completed, removed/unavailable. Material changes/cancellation override normal layout with persistent banner.

## Privacy
Private-home exact location absent unless authorization/disclosure policy allows it. Participant list obeys privacy/block rules.

## External ticket events
Ticket purchase and social “going/join Pod” semantics must not imply a ticket has been purchased unless we can verify it.

## Acceptance
Deep linkable; locale/time correct; source attribution/rights rules honored; sticky CTA accessible; share uses canonical event URL; report always reachable.
